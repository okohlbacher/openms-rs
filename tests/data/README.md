Unmodified BSD-3-Clause fixture from [OpenMS4-core at 7c029e8cdba6abab503708ecdd56f6ab55e38ce4](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/tests/class_tests/openms/data/Transformers_tests.dta). Copyright OpenMS Inc., Eberhard Karls University Tuebingen, ETH Zurich and Freie Universitaet Berlin; see the repository LICENSE and AUTHORS.

SHA-256: `69d552ec11db33256f09c1e403aecc45018f3d4c2553ba27112d8ebecd6d5297`

The file has 121 peaks and a maximum intensity of 46. Upstream Normalizer, ThresholdMower, NLargest and RankScaler tests use it. Threshold 10 retains 14 peaks; rank scaling produces minimum 96 and maximum 121. The precursor header is MH+ mass 739.771 and charge 2.

Rust tests port the original numeric assertions and add checks for array alignment, round trips, validation and scientific invariants. They do not invoke the C++ implementation.

## Signal processing and comparison fixtures

The `smoothing_*`, `baseline_*`, `comparison_*` and `peak_picking_*` fixtures
retain source provenance in the matching support documents under `docs/`.
Gaussian, Savitzky–Golay and morphology tables transcribe upstream assertions;
comparison DTA files are unchanged source fixtures. Peak-picking TSV files
extract the first spectrum of upstream instrument input and expected-output
files; they are not generated by running the C++ library in this project.

See [signal processing](../../docs/SIGNAL_PROCESSING.md),
[spectrum comparison](../../docs/COMPARISON_SUPPORT.md), and
[peak picking](../../docs/PEAK_PICKING_SUPPORT.md). The corresponding provenance
JSON files record source/fixture hashes and transformations. OpenMS-derived
fixtures retain the BSD-3-Clause copyright and attribution above.

## Identification and retention-time fixtures

The [FDR fixtures](fdr_provenance.json) extract source identification scores and target/decoy labels from the pinned OMSSA/X!Tandem/picked-protein examples. They are independent of the native idXML parser. The [idXML fixtures and schema](idxml_provenance.json) are byte-identical source copies used for reader assertions and independent writer validation. Numerical extraction details, hashes, and source-test limitations are recorded in those manifests and the corresponding support documents.

The [transformation fixtures](transformations_provenance.json) preserve weighted fits, interpolation and LOWESS reference data. These fixtures and Rust tests do not execute the C++ implementation.

The [basic protein inference fixture](protein_inference_provenance.json) extracts peptide/protein scientific fields from the upstream merger fixture; it preserves source scores/evidence while avoiding unrelated invalid XML dates. The [peptide indexing oracle](peptide_indexing_matcher_reference_provenance.json) records independent ambiguity/mismatch, enzyme and decoy-label expectations. These references test scientific behavior independently of optional XML parsing.

## Chromatogram integration and picking fixtures

The [chromatogram provenance](chromatogram_processing_provenance.json) records
19 pinned source hashes and five independently extracted tables. The four traces
retain all 146 source samples: glutamate (107), the negative-Simpson example (3),
and two SRM chromatograms (18 each). Integration, background, shape and picking
tables preserve the source's literal expected values and documented rounding.
Tests check native spectra and chromatograms, even-count Simpson neighbor use,
legacy/corrected boundaries and independent raw intensity sums.

The [mzML provenance](mzml_provenance.json) additionally identifies the source
binary-array implementation and pinned CV definitions used for the independent
auxiliary-array encoding and writer/schema tests. No C++ code was executed.

## EMG fitting fixtures

The [EMG provenance](emg_provenance.json) records six pinned source hashes,
429 literal samples across seven traces and the source's seven parameter/count
assertions. Minute and second coordinates are retained as separately declared
literals. Each sample records position f64 bits, raw intensity f64 bits and
container intensity f32 bits. Source full-curve loss assertions use raw f64
intensities with fitted parameters rounded to f32; these differ from the
optimizer's training loss.

The [EMG reference review](../../docs/EMG_REFERENCE_REVIEW.md) documents source
parameter tolerances, special-function checks and numerical limitations. These
fixtures were extracted from source text without executing the C++ library.

## Poisson/KL deisotoping fixture

The [deisotoping provenance](averagine_deisotoping_provenance.json) records
independent decoding of all 5,407 input peaks and all 104 expected output peaks
from the pinned source mzML files, without C++ execution or Rust processing.
The TSVs preserve every original binary value, including 4,514 input zeros.
An independently inferred seed/charge table maps every output peak uniquely
to the original input. The reference test compares the complete ordered output.

The source permits shared isotope extensions: two accepted seeds both use
input peak 4578. The default native Poisson/KL method preserves both clusters;
its explicit disjoint option returns the verified 103-peak subset. This behavior
and the source's threshold/top-N preprocessing are documented in
[model support](../../docs/AVERAGINE_DEISOTOPING_SUPPORT.md).
## Iterative centroiding, window filtering and mean noise

The [iterative provenance](iterative_provenance.json) identifies seven source
files, fourteen independently translated refinement configurations, 106 raw
samples and 16 seeds. Four TSVs retain source indices and binary32 encodings.
The original class test has no numerical goldens; the derived expectations are
not output from a C++ run. Two unchanged Orbitrap/FTMS input fixtures support
independent raw-sum, centroid-rounding and region checks. See the
[reference review](../../docs/ITERATIVE_REFERENCE_REVIEW.md).

The [window-filter provenance](window_mower_provenance.json) records the source
header, implementation, class test and reused 121-peak Transformers fixture.
Source assertions retain 56 sliding-window and 30 jumping-window peaks.
Independent small-case selection tests also cover ties, duplicates, ordering
and the source's last-window quota.

The [mean-noise provenance](mean_noise_provenance.json) records the byte-identical
2,526-point historical output and the shared source noise-input DTA. Tests
retain the source window of 40.1, sparse fallback of 2, minimum of 10 and absolute
output tolerance of 0.5. Additional independent rescans check clipping arithmetic,
signed signals and window boundaries. All data retain OpenMS attribution; no
C++ implementation was executed.

## Precursor purity and acquisition interchange

[precursor_purity_provenance.json](precursor_purity_provenance.json) records pinned
source hashes and four compact TSVs: 72 exact decoded peaks, seven spectrum
records, seven scalar/map results and eight SPS cases. Original rounded class-test
assertions are separate from independently calculated binary64 results. Peak
coordinates/intensities retain their exact binary64/binary32 bit patterns.

`precursor_purity_input.mzML` is an unchanged copy of the original 115,055-byte
source fixture. Its ASCII content declares Latin-1; the native-reader workflow
changes only that declaration in memory to UTF-8 and checks all seven scalar/map
cases using the complete original peak arrays. The extraction and workflow tests
do not execute C++. See [the reference review](../../docs/PRECURSOR_PURITY_REFERENCE_REVIEW.md)
and [supported behavior](../../docs/PRECURSOR_PURITY_SUPPORT.md).

## Fine isotope references

[fine_isotope_provenance.json](fine_isotope_provenance.json) identifies the pinned
sources, exact-count and numerical fixtures. The count table preserves all 44
usable class-test assertions, including full-support and high-coverage insulin
cases. Fourteen fructose mass/probability rows retain their original decimal
literals and source comparison policy; the bromine table has independent
binomial checks. Old loose class/header illustrations are kept distinct from
complete, higher-precision oracles. No C++ backend was run.

The [independent review](../../docs/FINE_ISOTOPE_REFERENCE_REVIEW.md) explains the
source's unnormalized f32 abundance/output rules, coverage boundary, labeled
isotopes and limits of equivalence with the absent IsoSpec layered backend.

## Fine isotope streaming references

## RNA digestion, modification generation and theoretical spectra

`rna_processing_provenance.json` records 28 pinned source hashes and seven new
TSV fixtures plus the reused 378-record RNA registry projection. The fixtures
retain twelve source digestion calls and 38 ordered product strings, fourteen
enzyme field records and 6,048 per-code predicate decisions, eight modification
strings/four count cases, and 132 original ion-mass literals with their binary64
encodings and source lines. Only 126 of those masses are actually compared in
the C++ tests; the six remaining full-length a/b/a-B values are marked as such.

`rna_processing_reference.rs` also checks complete independently enumerated
27- and 432-variant identity sets and source-derived branch behavior. Rounded
ion literals use an explicit 0.001 Da native tolerance; no unavailable source
macro default is asserted. The source multi-spectrum test's prepared Param is
never applied, so its effective default settings are recorded separately from
a new all-series/annotation comparison. See the
[independent review](../../docs/RNA_PROCESSING_REFERENCE_REVIEW.md).
