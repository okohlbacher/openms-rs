# Fixed metabolite isotope predictors

The private FeatureFindingMetabo predictor evaluates both source pretrained
models, `Metabolites2Percent` and `Metabolites5Percent`. It is an implementation
detail of feature finding, with no public SVM training, general model loader,
probability predictor or SimpleSVM compatibility claim.

The source is OpenMS4-core
[`82ce5b3`](https://github.com/okohlbacher/OpenMS4-core/tree/82ce5b373c97f934ffd9b1ffd80215ca66473d0b).
The four unchanged `.svm`/`.scale` resources are packaged in
[`resources/metabolite_isotope_models`](../resources/metabolite_isotope_models).
The native predictor uses these builtins; it does not search an installation,
environment variable or runtime override directory for replacement models.

## Calculation and integration

The caller supplies four raw binary64 features: capped monoisotopic mass and
the next three isotope/monoisotopic intensity ratios, with zero for missing
isotopes. The source caller computes `min(mz * charge, 1000)` without a lower
clamp and returns a separate `-1` result for singleton hypotheses. Those steps
belong to the main algorithm; this helper neither clamps nor inserts a
singleton policy.

Each feature is scaled as `(raw - center) / scale`. The models are binary
C-SVC/RBF with labels `[2, 1]`, respectively 548 and 999 support vectors, gamma
2 and 0.535887, and rho 22.9038 and 34.1652. Evaluation follows the source's
dense index order: subtract four feature pairs, accumulate their squared
differences, compute `exp(-gamma * distance)`, multiply by the row coefficient,
sum rows in model-file order, then subtract rho. A strictly positive decision
accepts label 2; zero accepts the second class, label 1, and is therefore rejected
by feature finding. No tolerance is added to the decision. Model `probA` and
`probB` values are unused by this classification operation.

Source anchors are
[`FeatureFindingMetabo.cpp`, lines 395–456 and 459–502](https://github.com/okohlbacher/OpenMS4-core/blob/82ce5b373c97f934ffd9b1ffd80215ca66473d0b/src/openms/source/FEATUREFINDER/FeatureFindingMetabo.cpp#L395)
and [`SimpleSVM.cpp`, lines 542–589](https://github.com/okohlbacher/OpenMS4-core/blob/82ce5b373c97f934ffd9b1ffd80215ca66473d0b/src/openms/source/ML/SVM/SimpleSVM.cpp#L542).
The separate tagged [LIBSVM v337 implementation](https://github.com/cjlin1/libsvm/blob/v337/svm.cpp#L320)
supplies the independently executed RBF/classification reference. Its tag is an
algorithm reference, not a claim that this SDK pins that external version.

## Precision and limits

[`generate_metabo_isotope_models.py`](../tools/generate_metabo_isotope_models.py)
checks the model kind, labels, dimensions and row counts, then converts every
used decimal into an explicit `f64::from_bits` value. The native test compares
all 7,755 coefficients, support-vector features and model/scale constants with
the original resource literals. Runtime prediction performs no model parsing.

All raw inputs must be finite. Finite scaling or distance overflow is retained:
positive infinite distance gives `exp(-infinity) = 0`, leaving the source's
finite decision. The immutable positive scales, gamma and bounded coefficients
make that behavior well-defined. Nonfinite raw values and exhausted cumulative
work return checked errors.

Each call precharges `32 * support_vector_count + 16` work units: 17,552 or
31,984. The main algorithm supplies the shared remaining budget. Successful
prediction uses fixed stack arrays and immutable static tables, with no heap
allocation and no byte-budget consumption. There is no partially published
prediction on failure. These are concrete operation limits rather than an
instruction-count or wall-time guarantee.

## Independent reference and validation

The [488-row fixture](../tests/data/metabo_predictor_libsvm.tsv) was generated by
compiling **unmodified LIBSVM v337** with the small
[test driver](../tests/data/metabo_predictor_probe.cpp), not by running the Rust
predictor. Each model has 244 inputs: fixed edge cases, a mass/ratio grid,
deterministic random inputs, inverse-scaled support vectors and boundary
neighborhoods. A separate Python calculation chooses boundary inputs only;
LIBSVM supplies every recorded decision and label. The smallest observed
absolute decision is about `7.13e-6`, clear of platform-dependent last-bit
ties. Both labels are exercised for both models.

The tests compare labels exactly and decision values within
`1e-10 + abs(reference) * 1e-11` to allow platform `exp` differences. The fixture
retains the actual observed binary64 bits. Additional independent dyadic and
cancellation examples check scaling, row order and the zero decision boundary;
resource tests cover exact and cumulative budgets and finite extremes. This is
a focused predictor comparison, not execution of the complete OpenMS SDK or its
full FeatureFindingMetabo class test.

Six focused tests pass on Rust 1.98 with all features and Rust 1.85 without
default features; strict scoped Clippy and formatting are checked separately.
The [manifest](../tests/data/metabo_predictor_provenance.json) records SDK and
external source hashes, compiler, fixture and generator identities. LIBSVM's
full [BSD notice](../resources/metabolite_isotope_models/LIBSVM_COPYRIGHT.txt) is
retained alongside the OpenMS model resources.

To reproduce, download the manifest-pinned `svm.cpp`, `svm.h` and `COPYRIGHT`
from the LIBSVM v337 tag into a separate directory and verify their hashes.
From the repository root, with `LIBSVM_DIR` naming that directory:

```sh
clang++ -std=c++17 -O2 -ffp-contract=off -I"$LIBSVM_DIR" \
  "$LIBSVM_DIR/svm.cpp" tests/data/metabo_predictor_probe.cpp \
  -o /tmp/openms-metabo-predictor-probe
python3 tools/generate_metabo_predictor_reference.py /tmp/openms-metabo-predictor-probe
python3 tools/generate_metabo_isotope_models.py --check
```

Add `--check` to the reference generator to compare an existing fixture without
replacing it. This exact-bit regeneration is appropriate on the recorded
compiler/platform; other platforms should retain the original fixture and use
the portable native numerical comparison. The original four resources and the
two generated tables have no runtime LIBSVM dependency.
