# Fine isotope reference review

<!-- SPDX-License-Identifier: BSD-3-Clause -->
<!-- $Maintainer: OpenMS Rust contributors $ -->

The independent [reference suite](../tests/fine_isotope_reference.rs) checks the native materialized fine-isotope generator against the pinned OpenMS4-core revision `7c029e8cdba6abab503708ecdd56f6ab55e38ce4`. Expected values came from source literals or separate chemical arithmetic, without building or executing C++. The [provenance manifest](../tests/data/fine_isotope_provenance.json) records twelve source hashes, fixture hashes, original decimal literals, and comparison policies. Tests work from an installed package without the reference checkout or development-time temporary files.

| Reference | Independent check |
| --- | --- |
| [44 source count cases](../tests/data/fine_isotope_counts.tsv) | Exact counts across absolute thresholds, relative thresholds, trimmed coverage, full finite support, fructose, carbon, hydrocarbons, insulin, and a large C/N/O composition |
| [14 fructose configurations](../tests/data/fine_isotope_fructose.tsv) | Complete literal mass/probability table at both absolute and relative `1e-5`; source comparison tolerance and stored binary32 probabilities |
| [Six CBr2 configurations](../tests/data/fine_isotope_bromine.tsv) | Source rounded masses/probabilities plus independently calculated isotope masses and two-atom binomial probabilities |
| Fructose coverage | Default selects three configurations; `0.99999` coverage selects seventeen, with the fourteen supplied source configurations retained |
| Insulin coverage boundary | The exact source count of 19,615 depends on summing stored binary32 probabilities into binary64 |
| Carbon mode and tail | Relative cutoff is measured from the most probable configuration, which need not be monoisotopic; configurations survive binary32 output underflow |

The strong fructose table comes from [IsoSpec_test.cpp](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/tests/class_tests/openms/source/IsoSpec_test.cpp#L95). Its helper compares multiplicative `1e-7` relative bounds without an absolute floor; reference probabilities have already been narrowed into `Peak1D`. The older [FineIsotopeDistribution_test.cpp](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/tests/class_tests/openms/source/FineIsotopeDistribution_test.cpp) contains less precise decimal values and uses the class-test default. That default cannot be established from this snapshot, which lacks `ClassTest.h`. The bromine fixture therefore states its own absolute allowance for the old literals and separately tests exact derived binary32 probabilities. No weaker class-test tolerance is attributed to the stronger table.

The header's nine-row C100H202 illustration is intentionally excluded as a selected-set oracle. It is incomplete and its final displayed probability falls below the stated relative cutoff. The executable source count of nine remains tested. Full-support counts such as `101 * 203 = 20,503` are retained as exact source expressions rather than presented as measured C++ output.

The source [formula adapter and total-probability trimming](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/openms/source/CHEMISTRY/ISOTOPEDISTRIBUTION/IsoSpecWrapper.cpp) establish two separate rounding steps. Natural isotope abundances pass through `Peak1D` binary32 before reaching the backend; materialized configuration probabilities are narrowed again on output. Neither is renormalized. For insulin `C520H817N139O147S8`, separate Python arithmetic finds a binary64 probability sum of approximately `0.9999899999250583` at 19,615 configurations, while summing the narrowed values gives `0.9999900005385141`. The latter crosses `0.99999`, matching the literal source count. The suite checks this crossing and verifies that removing the least probable retained configuration falls below the target. These sums are independently derived evidence, not recorded C++ results.

The numerical review checked mode construction, transfer completeness, canonical probability evaluation, fixed isotope treatment, charge handling, output rounding, and bounded allocation/work paths. The native enumerator retains every configuration identity, including equal-probability neighbors, and recomputes probabilities from counts instead of accumulating path-dependent updates. It charges state copies, hashing, probability calculations, heap operations, and final sorting; retained-state and output limits apply before growth. The full-support combinatorial preflight uses checked multiplication. No additional actionable defect remained after the review. Separate implementation tests exercise exhaustive small distributions, labels, charge, equal-probability modes, invalid inputs, and resource exhaustion.

Some boundaries remain explicit native behavior. The generator uses an ordered heap instead of IsoSpec's layered backend, whose implementation is not included in this snapshot. Threshold equality is retained. Coverage selects a minimal descending-probability prefix, with deterministic configuration ordering where probabilities tie; source tie identities and backend traversal order are not claimed. Source-style rounding can make total support sum slightly above or below one. A zero threshold requests complete support, including probabilities that narrow to zero. Positive formula charge adds natural hydrogen atoms and leaves masses undivided, following the pinned [FineIsotopePatternGenerator.cpp](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/openms/source/CHEMISTRY/ISOTOPEDISTRIBUTION/FineIsotopePatternGenerator.cpp), despite its deprecation notice; negative charge is rejected.

This evidence supports the materialized native generator and its stated limits. It does not claim the streaming/custom-enrichment IsoSpec wrapper interfaces, layered traversal, or full backend parity. Fine-isotope integration into theoretical spectra has a separate [reference suite](../tests/theoretical_fine_reference.rs).

Validation: seven independent reference tests passed with the current compiler and all features, and with Rust 1.85 without optional I/O features. Strict Clippy passed for both configurations. Formatting, the source hashes (now twelve including the theoretical-spectrum class test), three fixture hashes and row counts, development derivation hashes, and local document links were checked.
