# mzML binary whitespace normalization

The existing `LoadOptions.scientific.skip_xml_checks` now executes its source behavior. The default `false` removes exactly the four XML whitespace characters—space, tab, LF and CR—from each encoded binary string before Base64 decoding. `true` retains those characters. Despite its name, this option does not disable XML well-formedness, descriptor, Base64 alphabet/padding, declared-length, decoded-count, or resource checks.

The source pin is [82ce5b373c97f934ffd9b1ffd80215ca66473d0b](https://github.com/okohlbacher/OpenMS4-core/tree/82ce5b373c97f934ffd9b1ffd80215ca66473d0b). [MzMLHandlerHelper.cpp 138–148](https://github.com/okohlbacher/OpenMS4-core/blob/82ce5b373c97f934ffd9b1ffd80215ca66473d0b/src/openms/source/FORMAT/HANDLERS/MzMLHandlerHelper.cpp#L138) conditionally calls [StringUtils::removeWhitespaces](https://github.com/okohlbacher/OpenMS4-core/blob/82ce5b373c97f934ffd9b1ffd80215ca66473d0b/src/openms/include/OpenMS/DATASTRUCTURES/StringUtils.h#L523), whose predicate names those four characters. The native reader applies that exact condition in its existing text-retention loop, with no new buffer, parser, framework, or dependency. The former Unsupported-only `LoadOptions::validate` and its dead callers are removed; real selection, parameter, binary, header and XML limits remain in place.

Contiguous ordinary, zlib and all three Numpress payloads decode identically under both settings. Whitespace-bearing payloads normalize under the default; explicit skipping returns a checked error, from retained `encodedLength` or Base64 validation. If the declared encoded length includes whitespace, Base64 validation still rejects it. Default legacy stream `read` continues to normalize; scientific stream/path loading and retaining/nonretaining consumer delivery honor the flag. The writer ignores this read-only flag, as before.

Malformed Base64 remains a checked native failure rather than reproducing the source SIMD decoder's malformed-alphabet behavior (**CPP-055**, [issue log](../OpenMS_CPP_ISSUES.md)). Non-ASCII binary text, malformed XML, invalid padding and lengths do not become accepted. Vertical tab and form feed are illegal XML characters, not additional normalization characters. Strict malformed-payload rejection is an intentional native boundary; no C++ execution is claimed.

`fill_data=false` retains existing descriptor/XML validation and skips payload retention/decoding and binary allocation limits. Metadata-only reading still stops before record bodies. Count/setup passes do not decode binary payloads, regardless of this flag; a setup callback can therefore complete before the delivery pass reports an invalid binary payload. The established caller-visible callback effects and atomic retained-result contract remain unchanged. See [consumer support](MZML_CONSUMER_SUPPORT.md), [counts](MZML_COUNTS_SUPPORT.md), and [scientific loading](MZML_LOAD_OPTIONS_SUPPORT.md).

[Seven direct tests](../tests/mzml_normalization.rs) cover eight ordinary/zlib/Numpress fixtures under both settings; the four whitespace characters individually and together; strict alphabet/padding/XML failures; no-decode modes; setup before a failing delivery pass; plain/gzip/bzip2 paths and retained-result rollback; encoded/decoded lengths and cumulative budgets. The original source transform assertions are repeated with the skip flag both ways and retaining/nonretaining: **four spectra, forty peaks, TIC350**, from [MzMLFile_test.cpp 1258–1300](https://github.com/okohlbacher/OpenMS4-core/blob/82ce5b373c97f934ffd9b1ffd80215ca66473d0b/src/tests/class_tests/openms/source/MzMLFile_test.cpp#L1258). The reused fixture retains all source scientific/header records and binary text while fixing its five stale XML child counts; it is explicitly a prior source projection, not an unchanged original file.

[Fixture generation](../tools/mzml_normalization/source_fixture.py) independently uses Python `struct.pack`, Base64 and zlib, plus unchanged source MSNumpress class-test strings. No expected value is obtained from Rust output. [Provenance](../tests/data/mzml_normalization_provenance.json) records source/fixture hashes and those boundaries. Existing writer C and A/B/semantic modules are prerequisites only, excluded from this group's extraction; no additional MzMLFile capability is claimed.
