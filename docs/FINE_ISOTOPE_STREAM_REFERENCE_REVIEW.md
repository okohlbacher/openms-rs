# Fine isotope stream reference review

The independent [stream reference tests](../tests/fine_isotope_stream_reference.rs) cover the owning `FineIsotopeIterator`, raw `FineIsotopeConfiguration` values, threshold selection, and materialization from custom isotope populations. The [provenance manifest](../tests/data/fine_isotope_stream_provenance.json) records six pinned source hashes and references the existing fine-isotope TSVs by hash. No fixtures are copied from the Rust generator, and no C++ program was built or executed. Tests need neither the reference checkout nor temporary development files.

| Evidence | Checks |
| --- | --- |
| Ordered fructose stream | The first fourteen configurations match the complete source literal table; exhausting formula and custom natural-table inputs gives 2,548 configurations |
| Ordered insulin stream | The first 10,000 configurations satisfy the source accessor consistency checks and the documented descending-order contract |
| Threshold streams | Fructose counts of fourteen and insulin relative counts of 5,513/267 and absolute counts of 1,734/21; both formula and independently reconstructed custom natural tables |
| Custom materialization | Fructose produces fourteen configurations at either `1e-5` threshold and seventeen at coverage `0.99999`; output probabilities retain source binary32 rounding |
| Extra custom precision | Binary64 weights immediately above and below `0.5` remain distinct in raw values and logarithms, although both stored intensities round to `0.5` |
| Independent multinomial product | Six hand-derived configurations, including two distinct configurations at mass 122 and two equal-probability configurations without a prescribed tie order |

The [source class test](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/tests/class_tests/openms/source/IsoSpec_test.cpp) supplies the fourteen fructose literals and exact counts. Its comparison helper uses multiplicative `1e-7` bounds with no absolute floor. Its insulin prefix supplies accessor checks, not additional literal masses or probabilities. The native test adds an explicit descending-order assertion from the [ordered-generator header contract](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/openms/include/OpenMS/CHEMISTRY/ISOTOPEDISTRIBUTION/IsoSpecWrapper.h). The source prefix helper accidentally advances one extra uninspected configuration because of its loop-condition order; that side effect is not treated as required API behavior.

Natural custom tables in this suite come directly from original C/H/N/O/S decimal strings in `ElementDB.cpp`, independently of the Rust element lookup. Probabilities are narrowed to binary32 and widened before being supplied as custom binary64 inputs, recreating the source test's `ElementDB` → `Peak1D` → custom-vector path. Natural tritium's zero probability is omitted. Upstream directly tests custom natural-table fructose; applying the same source tables to insulin's formula-count assertions is an additional adapter consistency check, not a separate upstream custom-insulin golden. The enriched toy examples deliberately retain full binary64 inputs and therefore test precision absent from the upstream natural-table fixture.

The two-population example combines a count-two binomial with masses `[10,11]` and weights `[0.25,0.75]` with a count-one population having masses `[100,102]` and weights `[0.6,0.4]`. Its six probabilities follow direct multiplication, without heap traversal or logarithmic reference code. The states at mass 122 have probabilities `0.3375` and `0.025`, demonstrating that equal mass does not make two configurations interchangeable. These mathematical values use separately stated numerical tolerances rather than being attributed to captured source output.

## Source contracts and native boundaries

The [wrapper implementation](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/openms/source/CHEMISTRY/ISOTOPEDISTRIBUTION/IsoSpecWrapper.cpp) exposes raw binary64 probability and log probability independently of its binary32 `Peak1D` representation. Accordingly, `to_peak()` must retain mass exactly and narrow probability only at conversion. A finite log probability can remain useful after raw probability underflows to zero. The source declares current-state accessors undefined before the first successful advance and after exhaustion; the native iterator instead yields owned values and remains fused after exhaustion or a terminal error. Separate adversarial tests cover underflow and checked public-field conversion.

Raw formula constructors inspect the atom map and ignore formula charge. They therefore differ deliberately from `FineIsotopePatternGenerator::run`, which preserves the source's positive-natural-hydrogen addition and negative-charge rejection. Custom input has no implicit element lookup, charge modification, probability normalization, or early binary32 narrowing. Source custom-vector checks cover outer lengths and weights greater than zero; the native API additionally validates complete shapes, finite values and resource bounds. The redundant source `isotopeNumbers` vector is inferred from row lengths in the native API.

The consuming threshold methods filter the remaining stream and retain the original global mode as the relative reference. Absolute thresholds compare the returned raw binary64 probability directly with the threshold. Relative thresholds compare `probability / mode_probability` when both probabilities are finite and positive, and otherwise use the canonical logarithmic cutoff to handle underflow or overflow. Relative values above one select nothing; zero admits the remaining support, including underflowed probabilities. These comparisons retain equality with returned values and reject the next larger representable cutoff without an epsilon allowance. The existing materializers continue using logarithmic threshold comparisons, preserving their earlier numerical behavior. This iterator-only boundary policy is explicit native behavior; the absent backend's exact threshold boundaries are not claimed.

Threshold changes do not restart an exhausted iterator or recover previously consumed states. Deterministic tie order, owned values, and fused errors are also native contracts, not claims about undefined source states. The ordered stream can stop after a prefix of a support too large to materialize; materialization still observes its output cap. Separate implementation and adversarial suites check these state and resource policies.

Read-only implementation review checked custom table validation before copying, source formula-charge separation, raw versus stored probability arithmetic, deferred neighbor expansion, persistent work limits, and configuration identity. It found that raising the cutoff above the last yielded configuration could still expand an entirely excluded remainder and fail on a resource limit. The implementation now checks the original-mode and pending-state cutoffs before expansion; equality still permits tied configurations. A separate adversarial regression exercises this with a large custom category table. All mode, pending-state and popped-state checks use the same comparator. A later independent boundary review prompted the raw-value iterator policy above, with adjacent-binary64 cutoff regressions in the separate numerical suite.

IsoSpec's total-probability generator uses its `p` value only as a traversal hint and can continue to full support. This increment does not expose a hint API or pretend the stream stops automatically at a coverage target. The ordered traversal and custom materializer do not reproduce IsoSpec layers, untrimmed layer-dependent selected sets, or quickselect tie identities. Those remain outside the implemented surface. The source backend's implementation is absent from the pinned snapshot, so source order and membership beyond the documented contracts cannot be inferred from wrapper calls alone.

The existing [materialized fine reference review](FINE_ISOTOPE_REFERENCE_REVIEW.md) continues to document the forty-four count cases, binary32 coverage boundary, isotope labels and full-tail behavior. This suite adds independent evidence for the new stream and custom-input interfaces without weakening those earlier checks.

Validation: all six independent tests passed with the current compiler and all features, and with Rust 1.85 without optional I/O features, including reruns after the iterator threshold comparison change. No source counts or golden values changed. Strict Clippy passed for both configurations. Formatting, six source hashes, two reused fixture hashes and row counts, and local documentation links were checked.
