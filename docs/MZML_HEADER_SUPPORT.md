# mzML experimental headers and references

The mzML stream/path readers and both ordinary/Numpress writers transport the source-supported experimental header fields from SDK `82ce5b373c97f934ffd9b1ffd80215ca66473d0b`. They use the existing `MSExperiment.settings` owner and the full five-provider `ControlledVocabulary`; no second metadata map or reduced vocabulary is introduced. This completes the header/reference operation group. It does not complete `MzMLFile`, centroid inspection, every mzML schema element, or format-specific semantic validation. [Streaming consumers and transforms](MZML_CONSUMER_SUPPORT.md) are implemented as a separate operation group.

## Public operations and fields

Existing `mzml::read`, `read_with_options`, scientific loading and compressed path loading share one header registry. `read_metadata` and `read_metadata_with_options` return `ExperimentalSettings` without materializing records. `LoadOptions.scientific.metadata_only` returns an experiment containing those settings and empty spectrum/chromatogram vectors. The reader resolves the first list's required default processing reference and stops at its opening tag, before interpreting its count or reading binary/tail content. A document with no record list finishes normally. Unused scientific selection limits are not charged. [Disabled record population](MZML_CONSUMER_SUPPORT.md) now supports `fill_data=false`; other unimplemented scientific options remain explicit errors.

| XML owner | Native payload |
|---|---|
| mzML/run | Document accession, `mzml_id`, full run DateTime and retained raw timestamp, fraction identifier, typed run metadata |
| fileDescription | Ordered contacts; source-file names, paths, checksum/type, file/native-ID format and scalar metadata |
| sampleList/run sampleRef | Referenced sample name/number/mass/volume/concentration/state/comment, ordinary metadata and source PATO/BTO/GO routes |
| softwareList | Software name/version and typed scalar metadata; shared lookup is resolved before owned software copies |
| instrumentConfigurationList | Default instrument plus additional keyed configurations, software, customizations, instrument model and ion optics; complete source component enum/scalar/metadata routes |
| dataProcessingList | Encounter-ordered processing methods, software, actions, thresholds, completion DateTime and scalar metadata |
| records and auxiliary arrays | Default/explicit processing references; auxiliary float/integer/string array names, scalar metadata and processing histories |
| scans and precursors | Source-file name/path metadata, external spectrum IDs; scans can reference defined additional instruments |

The 116 instrument enum/accession pairs are independently projected from both C++ reader and writer branches and checked against source header discriminants. Remaining enum variants or stored fields that the source mzML writer cannot represent are rejected. Partial nonempty instruments must contain source, analyzer and detector families, as required by the XSD; an entirely empty instrument omits its optional component list. Component order retains the signed source scalar domain (`xs:int`). Unknown model/file/native-ID names, conflicting accession overrides and overrides with units are checked errors. Custom software names use the custom-software term rather than a lossy spelling alias.

Source files are deduplicated by complete value in lexical input-ID order. Record-only source files written into the document become global settings source files on reading, matching source list collection. Source-file size and arbitrary CV-term payload have no source writer representation and are rejected. A chromatogram cannot carry `sourceFileRef` in mzML: nondefault attached chromatogram SourceFile values and such input attributes are rejected. Spectrum source-file references and scan/precursor name/path references are supported. Additional instrument IDs retain caller identity; whitespace-normalized or generated-ID collisions fail before output.

Every processing reference clones only Arc handles after its definition has been parsed and validated. References to one definition share Arc identity. Equal histories can be deduplicated during writing; no pointer identity is serialized. Methods retain XML encounter order on reading, as the source does, while writing emits their actual indices rather than repeating order zero. All list counts match the emitted definitions, including every array kind.

## Metadata and numerical fidelity

Headers, precursors and auxiliary arrays preserve strings, signed native integers, finite doubles and represented MS/UO units through the scalar codec. Empty/list values have no reversible scalar XML representation and fail before output. Source CV integer conversion narrows to i32 before native storage; user integers retain i64. Instrument/sample parsing follows source ListParse whitespace and leading-plus rules. BTO/GO lookup uses the full provider and preserves only fields actually consumed from its historical encoding.

CV promotion uses the independently projected source mapping-path membership rules, but only when the exact reader route returns the same metadata key/type. Otherwise a user parameter preserves the value. This fixes software metadata's wrong source mapping path and avoids moving ordinary metadata into a different dedicated field. All CV parameters precede user parameters. This is not MUST/cardinality/type/unit semantic validation or a replacement for the general mapping/validator APIs. Unknown terms ignored by source branches remain ignored; unresolved references and malformed recognized owners are checked errors.

Legacy spectrum/chromatogram metadata is still string-valued. String, unit-free primary-array metadata is merged into that map: m/z before intensity for spectra regardless of XML order; XML encounter order for chromatograms. Incoming primary keys overwrite earlier keys exactly as source metadata addition does. Non-string/unit-bearing primary metadata and independent primary-array processing history are explicitly rejected because the current record has no owner for them. Auxiliary descriptions remain attached to their actual arrays through raw-f64 filtering, narrowing and aligned permutations.

`DataProcessing.completion_time` is now `Option<data_structures::DateTime>`, replacing `Option<CompletionTime>`. This is an API migration for explicit field construction; `.parse()` literals normally infer the new type. `None` denotes the source unset timestamp. Graph `ProcessingStep` retains its separate `CompletionTime` API. mzML, FeatureXML and ConsensusXML now preserve seconds and represented milliseconds. Writers reject invalid dates, inconsistent partial states and years outside 1–9999 before external output. Existing DateTime format/getter APIs perform the conversion; no timestamp shadow metadata is introduced. A stored raw run timestamp is reused only if its full parsed DateTime equals the current field, including milliseconds. Sample signed zero is preserved.

## Empty history and empty action sets

The schema requires a processing definition even for a native empty history. The writer emits one ConversionMzML method with exact fallback software name `OpenMS Rust mandatory mzML processing placeholder`, version `1`, and scalar marker `openms-rust:empty-processing-history="1"`. Only that exact payload normalizes back to empty. Real source conversion methods without the marker survive.

An individual method with an empty action set emits a generic DataProcessing term plus `openms-rust:empty-processing-actions="1"`; its real software, timestamp and metadata remain. Only the action and marker are removed on reading. Both marker keys are reserved on native output. Reader eligibility checks raw element/attribute kinds, parameter/ref child shape, action multiplicity, discarded action values/units and ignored completion-time units, followed by complete semantic payload checks. Extra software payload or a forged marker cannot be silently discarded.

## Bounds and failure behavior

Header capture, registry construction, reference expansion, metadata copying, deduplication and planned XML output use one cumulative 50,000,000-work/256 MiB allocation allowance per operation, separate from the existing XML/parameter/binary/selection limits and the immutable CV singleton's own initialization allowance. Every pre-run descriptor participates in `ReadOptions.max_total_params/max_param_bytes`; referenced parameter payload is charged again for each use. Retained header nesting is limited to 16. Full inline map value types are precharged before insertion, including sparse root capacity; vector minimum/geometric capacities and deep owned copies are covered. Shared processing attachments charge handles, not repeated deep copies. The shared data-array meter now conservatively charges at least 11 complete element slots for a nonempty BTree root, including large inline values; this can reject previously undercharged small custom allocation limits earlier.

Read operations build owned results, and path replacement stays transactional. Writer semantic/size failures occur before any external write. After output begins, external I/O failure can leave a partial stream, as for ordinary Rust writers; atomic path publication remains handled by the existing path layer. Neither format provides a promise to validate the unread metadata-only tail. Plain/gzip/bzip2 paths use the existing bounded, content-sniffed reader and atomic store transport.

## Evidence and source corrections

`tests/mzml_header.rs` combines upstream class-test literals with independent source projections, all 116 enum routes, reference/Arc identity, both binary writers, metadata-only stop, source primary merge order, fractional timestamps in all three formats, exact markers, malformed placement and unchanged-output failures. Private regressions exercise cumulative source copies, handle-only processing references, full registry map precharge and sparse large-value roots. The rich header fixture is validated by the pinned mzML XSD when `xmllint` is available. The original fixture is retained; the projection removes record payload and corrects only its three stale sample/software/processing counts. Historical parameter-group tests explicitly repair the same stale declarations without changing their frozen binary fixture.

The source-derived generators never invoke Rust production to create expected scientific values. Source hashes and fixture/generator identities are in `tests/data/mzml_header_provenance.json`. [Original C++ issues](../OpenMS_CPP_ISSUES.md) distinguish source inspection from executed evidence: CPP-019 count mismatch, CPP-025 missing later action fallback, CPP-026 repeated zero order, CPP-027 completion-time truncation, and CPP-028 wrong software mapping path are corrected here. Centroid option mutation CPP-018 remains outside this operation group. XML escaping is applied consistently, including software version and fraction identifier; the raw software version/fraction/checksum source omissions are recorded as CPP-041. Software version and fraction quote/ampersand regressions preserve valid values; arbitrary non-hex checksum text retains the existing native digest validation and fails before output.

## Focused validation

Rust 1.98 with all features passes 146 adjacent public tests and five private resource tests. Rust 1.85 with default features disabled and `mzml,featurexml,consensusxml` enabled passes 145 public tests and the same five private tests; the one-test difference is the existing idXML-only array guard. Both configurations pass all 21 dedicated header tests and strict library/changed-test Clippy. Scoped edition-2024 formatting passes. The actual libxml2 `xmllint` executable validates both rich-header writer outputs against the retained mzML XSD, including a chromatogram, both marker shapes and escaped fraction text. The six fixture projections and formatted mapping table regenerate byte-for-byte from the pinned source; all 30 recorded source, fixture, generator and reused-fixture hashes match. No new C++ build or execution is claimed.
