# mzML acquisition records

The mzML reader and both ordinary/Numpress writers now transport spectrum `AcquisitionInfo`: a combination method, ordered `Acquisition` records with identifiers and scalar metadata, and scalar metadata on the scan list. This is a bounded addition to the existing [settings transport](MZML_SETTINGS_SUPPORT.md), not a full mzML metadata registry or `MzMLFile` port.

`ReadOptions.acquisition_mode` defaults to `AcquisitionMode::Canonical`. Every scan is initially retained in source order. At spectrum completion, Canonical mode collapses the entire acquisition value to its native default only when there is exactly one scan, its identifier and metadata are empty, scan-list metadata is empty, and the combination is absent or `no combination`. Multiple scans, any metadata key (even an empty string value), an identifier, or sum/mean/median makes the list informative: every scan, including empty neighbors, remains. `AcquisitionMode::Source` disables this normalization and retains every actual scan. Stream, scientific loading, file-path loading and atomic replacement all honor the same field. Documents without a scan still produce no acquisition in either mode.

The source writer emits at least one scan when writing a scan list, and substitutes `no combination` for an empty method. Those two normalizations are observable: an empty method in an informative list reloads as `no combination`; an explicit default singleton reloads as empty in Canonical mode. An empty vector with informative list metadata or a nondefault combination gains a dummy scan on writing. Source mode retains that scan, but cannot infer whether it was originally implicit. No private identity marker is emitted. As in the previous native settings writer, completely empty acquisition/settings with missing RT (`-1`) can omit the whole scan list; it does not invent a scan time.

The four method names are exact, case-sensitive source names: `sum of spectra`, `median of spectra`, `mean of spectra`, and `no combination` (MS:1000571/1000573/1000575/1000795). Unknown native methods fail before output rather than silently falling back. IDs use escaped `externalSpectrumID`, including whitespace and XML-sensitive characters. RT and scan windows belong to the first scan; zoom is emitted on every scan. The native writer places zoom before acquisition user parameters to satisfy the XSD CV-before-userParam order; the source puts zoom after metadata and can produce invalid XML for their combination. Existing scan-time multiplicity, binary decoding, aligned filtering and Numpress policies are unchanged.

## Metadata and header references

`scanList` user parameters map to `AcquisitionInfo.metadata`; `scan` user parameters map to the current acquisition. They reuse the existing typed scalar codec, preserving strings, signed integers, finite doubles and represented MS/UO unit identities. Empty/list values are rejected before output because mzML scalar parameters cannot preserve those native types. Duplicate metadata keys and duplicate combination CVs are checked errors, including collisions between inline and referenced parameters.

A source-audited table covers the nine acquisition fallback CVs among the 28 pinned scan-attribute/direction/law descendants:

| Accessions | Native value |
|---|---|
| MS:1000927, MS:1002082, MS:1002083, MS:1003371, MS:1003394 | finite double |
| MS:1003057 | source signed i32 converted to native integer |
| MS:1002527, MS:1002528, MS:1002892 | string, including empty |

These values use the accession as the metadata key. Writing them as ordinary `userParam` is the source writer's fallback too: it searches metadata keys by CV **name**, so accession keys are not promoted. Arbitrary ontology lookup/name promotion and other scan CVs remain outside this adapter's existing supported subset; in particular, spectrum drift time and the source's other spectrum-level typed CV projections are not newly represented. The previous unknown/out-of-scope CV policy is unchanged. No complete CV registry is claimed.

The reader collects only source-file ID/name/location and instrument-configuration IDs/default ID. A scan `sourceFileRef` becomes the source's `source_file_name`/`source_file_path` scalar metadata. The source's deterministic lexical repairs are retained: an empty location splits the name on either slash style; a missing directory becomes `file://./`; `File://`/`FILE://` and `file:///.` substitutions occur in source order; root `file:///` becomes `file://`. Even the source's repeated slash result for `file:///./data` is retained. Filesystem-dependent relative-to-absolute resolution is deliberately excluded; parsing does not probe source directories or depend on the host's working directory. Writing keeps the resolved scalar metadata rather than inventing a source-file header or reconstructing `sourceFileRef`, also matching the source's fallback.

A nondefault `instrumentConfigurationRef` becomes `instrument_configuration_ref` metadata. A reference to the run default adds no metadata. Header IDs and references are validated, and duplicate IDs/count mismatches fail. Writing an acquisition with `instrument_configuration_ref` fails before output because full instrument definitions are not retained. `spectrumRef` remains ignored as in the source; it is not an acquisition identifier. Full SourceFile attachment/header round trips and instrument registries remain separate work.

Chromatogram AcquisitionInfo has no source mzML location and remains rejected, together with chromatogram InstrumentSettings, record SourceFile/DataProcessing and spectrum InstrumentSettings metadata. Existing singular chromatogram Product and spectrum Product-list support is unchanged.

## Bounds and evidence

Scans, source files, instrument IDs and run descriptors share the existing parameter count/byte budget with parameter definitions, reference uses and expanded applications. Declared scan/header counts are bounded before records are accumulated. Every resolved source-file name/path copy is charged before allocation; short references cannot multiply a large retained string without consuming the same cumulative budget. Source-file normalization temporaries are precharged. All records, including excluded records, follow the existing full validation policy. Supported output acquisition metadata shares the fixed cumulative 50 million work / 256 MiB settings preflight before validation or output; ordinary and Numpress writers use the same path. Path replacement remains atomic on errors.

The [provenance manifest](../tests/data/mzml_acquisition_provenance.json) records source hashes, exact source test locations, the [projected source fixture](../tests/data/mzml_acquisition_source_projection.mzML), and regeneration steps. The original source fixture is reused unchanged by hash. The projection retains all six acquisition IDs and source scalar metadata across four spectra; it strips unrelated unsupported fields/binary payload and preserves settings/Product literals. Its sole malformed structural repair changes the source Product list's declared count from one to its two actual products, both asserted by the source class test. It is labeled a projection, not an untouched source fixture.

Tests cover the source literals, all four methods/nine typed fallback CVs, both normalization modes, informative empty neighbors, escaped identifiers, metadata/unit preservation, header resolution and lexical repairs, malformed/duplicate references, cumulative expansion bounds, excluded records, first-scan placement, both writers, file loading/rollback and independent XSD validation when `xmllint` is available. No C++ build or execution was used for this increment; expected values come from source literals or explicitly derived source branches.
