## Third-party code: crates first

The source reaches one external library: Boost.Math's
`binomial_distribution` pdf, for the static averagine table of
`computeAveragine_` (200 bins of 10 probabilities). `statrs` 0.18, the crate
the port already carries for Boost.Math, was measured against the Release
build's table: it evaluates `exp(ln C(n, k) + k ln p + (n - k) ln(1 - p))` with
a Lanczos `ln_gamma`, where Boost goes through its incomplete-beta derivative
and glibc's `pow`/`exp`/`log`. The two agree to about 1e-12 relative and differ
in the last bits of most large-bin entries (bin 165, isotope 0:
`0.0005107042342232764` against `0.0005107042342238168`). Since the table is a
constant of 2000 numbers, the Release build's own values are embedded
(`averagine_table.rs`, generated by `../oracle/FF4-biosaur2/make_table.py`
from the oracle dump) and `statrs` stays the independent check
(`averagine_table_is_the_binomial_model`, 1e-9 relative). No dependency is
added. The TOF filter's `log10` and `pow` use the `libm` crate (already a
dependency) rather than the platform library, so the thresholds do not depend
on the host; the TOF oracle case matches bit for bit.

## Preserved source conventions

- **Every `std::sort` is the Release build's introsort**
  (`math::source_sort::source_sort_by`): the peaks of a scan by descending
  intensity (`linkScanToHills_`), the hills by weighted m/z
  (`detectIsotopePatterns_`), the patterns by isotope count and cosine
  (`selectNonOverlappingPatterns_`), the PASEF peaks by m/z bin, the FAIMS
  reassembly by retention time (`MSExperiment::sortSpectra(false)`), and the
  medians. Equal keys land where the C++ puts them; the `syn_ties` case (no
  m/z jitter) exercises it.
- **`static_cast<int>(double)`** is `cvttsd2si` (`i32::MIN` out of range): the
  m/z, ion-mobility and averagine bins.
- **`cosineCorrelation1D_`'s `omp simd reduction`** is summed as the Release
  build's SSE2 loop sums it: two lanes over even and odd positions, an odd tail
  added to the even lane, then `(even + 0.0) + odd`
  (disassembly at `libOpenMS.so 0x19134d0`, `../oracle/FF4-biosaur2/results/`).
  A serial sum differs in the last bits, and those feed the ranking of
  patterns.
- **The FAIMS path** splits with `ImDataConverter::split_by_faims_cv`, processes
  the groups (in parallel, like the source's `omp parallel for`, with a
  thread-count-independent result), converts each group's features, merges
  across voltages with `FeatureOverlapFilter::merge_faims_features(5.0, 0.05)`
  in the source's fidelity, and reassembles the stored experiment: the
  spectra of the groups in ascending voltage order, sorted by retention time,
  with the chromatograms and settings kept.
- **Non-FAIMS features** carry drift time -1, so `FAIMS_CV` is not written.
- **The TSV writers** print doubles as `std::ostream` does at precision 6.
- **Unique ids**: each feature, then its map, draws from the generator in the
  source's order; under `-test` the tool's ids equal the Release build's.
- **Every log line** of the source is returned in order with the source's
  text and number formatting, except the timing suffixes (below).

## Native differences

- **A failed run leaves the stored data unchanged.** The source removes the
  non-MS1 spectra, centroids and TOF-filters in place before it can throw
  (for example `No MS1 spectra found` after the MS2 spectra are gone, or
  `Ion mobility array shorter than peak list.` in the hill linking). The port
  works on a borrowed working set and commits only on success.
- **Refusals where the source has undefined behaviour**: a non-finite m/z or
  intensity of a peak inside the window, a non-finite MS1 retention time, a
  parameter field its parameter would refuse (the fields are public).
- **`Biosaur2Limits::max_isotope_combinations`** (default 2^24 per hill and
  charge) is preflighted; the source enumerates the whole Cartesian product.
- **`calibrateMass_`'s retry with 0.25 ppm bins** cannot recurse without end
  here; no finite input reaches that branch.
- **Ion-mobility peak type.** The native spectrum stores no `IMPeakType`, so
  the source's two uses are not reproduced: its skip of PASEF centroiding for
  data annotated `IM_CENTROIDED` (such data is centroided again), and its
  `IM peak type: ...` info line; nor does the port mark centroided spectra
  `IM_CENTROIDED`. The source mzML reader annotates `IM_PROFILE` unless a
  spectrum carries `MS:1003441`, which the native reader does not keep
  (see `TOPP_FEATURE_FINDER_CENTROIDED_SUPPORT.md`).
- **Timing text**: log lines ending in a `StopWatch` timing are returned
  without it; the timing-only lines (`PASEF centroiding ... took`, `Hill
  calibration ... took`) and the tool's four timing lines and progress
  sections are not written.
- **Log order under FAIMS** is the serial order; the source's parallel groups
  interleave their lines.
- **The debug parameter line** of `updateMembers_` is not reproduced.

## Source defect candidates

Not registered in `OpenMS_CPP_ISSUES.md` (the lead's file); listed in the lane
report.

1. `buildFastMzLookup_` bins hills with the hill tolerance `htol` and looks up
   one bin either side, so isotope candidates further than about `2 * htol`
   ppm from the expected position are never seen, whatever `itol` says; with
   `itol` above twice `htol`, `itol` is not honoured.
2. `cosineCorrelation1D_`'s `omp simd reduction` makes the correlation, and
   through it the pattern ranking, depend on the compiler's vector width: an
   AVX build sums in four lanes and can rank ties differently from the SSE2
   Release build.
3. `static_cast<int>` of `mz / mz_step` (and of the ion-mobility and averagine
   quotients) is undefined for a small positive `htol` or `paseftol`; the
   parameters accept any non-negative value.
4. On FAIMS or drift-time data without per-peak ion mobility,
   `processFAIMSGroup_` counts every spectrum as having ion-mobility data and
   logs `Applying PASEF/TIMS centroiding ...` followed by `PASEF centroiding: N
   peaks -> 0 centroided clusters`, although nothing is centroided.
5. The header documents `Hill::drift_times` and `ion_mobilities` as *empty if
   not available*; both always hold one entry per peak (-1 when absent).
   `centroidPASEFData_` documents `mz_step` as `[out]`; it is an input.
6. `performInitialIsotopeCalibration_` runs an O(hills x charges x window)
   search whose result is discarded; `checkIsotopeValleySplit_` is never
   called.
7. `run` modifies the stored experiment before it can throw, so a failed run
   leaves the MS2 spectra removed and the data centroided.
