# RNA processing reference review

This increment independently checks modification-aware RNase digestion, fixed and variable RNA modification generation, and single/multiple theoretical RNA spectra against OpenMS4-core revision `7c029e8cdba6abab503708ecdd56f6ab55e38ce4`. The [reference test](../tests/rna_processing_reference.rs) uses packaged fixtures; it does not require a checkout of the C++ source. No C++ program was built or executed, and no expected value was obtained by running the new Rust implementations.

The [manifest](../tests/data/rna_processing_provenance.json) records the pinned source hashes, original lines, effective spectrum settings, fixture hashes, and the distinction between literal and independently derived assertions. Source code and class-test excerpts carry BSD-3-Clause attribution. MODOMICS resource terms remain a separate boundary documented in [RNA data notices](../resources/rna/README.md); hashing or testing a resource does not establish redistribution rights.

## Literal coverage

| Scope | Packaged evidence | What the reference tests assert |
|---|---|---|
| RNase digestion | 12 source calls and 38 output strings, including the repeated cusativin case | Complete product identity and order; the source missed-cleavage and terminal settings |
| RNase definitions | 14 enzyme records and 16 distinct code expressions | Every projected scientific field and 6,048 expression/code decisions over all 378 source records |
| RNA modifications | One fixed output, seven single-placement strings including the original, four count cases | Fixed typed equality; counts 7, 6, 27 and 432; complete variant identities for the 27/432 cases |
| RNA spectra | 132 decimal literals, including their binary64 encodings, from two sequences and nine ion series | All 126 values actually compared by the source; exactly seven peaks in each of 18 isolated-series runs |

The RNase predicate table was first calculated with Python's standard-library `re.search` over the literal registered expressions. It was then independently cross-checked using direct substring, anchor and immediate-lookaround predicates. These expressions are finite and inspected; this does **not** establish equivalence for arbitrary Boost regular expressions. The tests also use synthetic multi-occurrence codes to check that a forbidden first match does not suppress a valid later match.

The ion references come from [NucleicAcidSpectrumGenerator_test.cpp](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/tests/class_tests/openms/source/NucleicAcidSpectrumGenerator_test.cpp). That test attributes its values to Ariadne. Each a-B, a and b vector contains an eighth, full-length value that the test does not compare. All six unused literals remain in the fixture with `compared_by_source=false`; they are not asserted as generated peaks. The 126 compared values use an explicit native tolerance of 0.001 Da. The pinned snapshot omits the implementation establishing the default `TEST_REAL_SIMILAR` tolerance, so this tolerance is not presented as an exact reproduction of that macro. Decimal strings and their bits identify the published references, not C++ runtime observations. Label and unit-intensity checks follow the configured generator behavior rather than additional literal class-test assertions.

The multiple-spectrum source section changes a local `Param` but never calls `setParameters`. Its actual test therefore uses default b/y ions, no metadata, first prefix disabled, no precursor, charges {-1,-3,-5} and base -1. The native reference preserves those actual settings and compares the three outputs to independent single-spectrum calls. Counts 13, 39 and 65 are derived from six b ions plus seven y ions at each included charge; they are not new upstream literals.

## Independently checked behavior

RNase cuts operate on complete raw nucleotide **codes**, not biological origins or bracketed sequence display. In particular, `G|A(?!m)` permits Gm, `.*(?!m)$` matches even a code ending in m, and RNase_4's closing-bracket alternative differs from RNase_4p/4c's `m1Y`. Product order is start boundary first, increasing missed-cleavage count second. A coordinate oracle records the six half-open intervals in the source's missed-two T1 example. A separate sulfur case verifies that enzyme end gains overwrite the end installed by slicing, including an explicit null gain. RNase_H remains an ordinary cleavage enzyme, so its missed-cleavage setting controls products; it is not equivalent to unspecific substring enumeration. The mazF test checks that its three lookarounds are evaluated on separate records and boundary zero is not considered.

The [modification source](https://github.com/okohlbacher/OpenMS4-core/blob/7c029e8cdba6abab503708ecdd56f6ab55e38ce4/src/openms/source/CHEMISTRY/ModifiedNASequenceGenerator.cpp) has defined differences between its maximum-one shortcut and its general enumeration. Maximum one scans residues right-to-left, accepts matching-origin records of any terminal specificity into a residue slot, and never creates terminal-slot variants. The general path filters residue candidates to Anywhere specificity and ignores origin when filling empty terminal slots. Empty maximum-one input is a defined no-iteration case: the source custom iterator uses signed index -1 at both adjusted endpoints. General enumeration can emit terminal-only empty sequences.

Fixed modification processing chooses the first compatible record at an empty terminus and the last compatible Anywhere record at an originally unmodified residue. An explicit typed-state oracle verifies these choices, source terminal-site order (three-prime, five-prime, then residues), reverse subset order and last-selected-site-fastest alternative nesting. Complete Cartesian identity checks for the 27 and 432 cases do not reuse the production subset traversal.

Source candidate sets use pointer identity and allocation-dependent order. Native caller-slice order is a deliberate deterministic replacement. Repeated copies of one Arc are removed; equal records from separate allocations remain separate alternatives and can produce equal-valued duplicate sequences. The tests distinguish those cases by allocation identity. A terminal-specific record installed into a residue slot remains usable as a typed sequence, while checked serialization rejects relocation through the ordinary parser.

Theoretical fragment accumulation uses each record's declared monoisotopic mass, while some precursor fallback paths use a complete sequence formula. These fields are intentionally independent in the RNA foundation. A source-derived test checks the optimized precursor's omission of the first sulfur linkage when both fragment ladders exist; the formula-only fallback includes that linkage. Another independently checks a-B ambiguous modification splitting into two half-intensity peaks separated by CH2. The stored-charge conversion and final sorting preserve source conventions; finite source quirks are not silently normalized into a different chemical model.

## Limits of this evidence

These are source-literal and independently derived tests, not a differential comparison against a running C++ binary. Arbitrary Boost-regex compilation, the RNase XML parser interface and the `IdentificationData` graph digestion overload remain separate coverage gaps. The native coordinate products are useful for graph integration but do not implement the graph's parent registration and merging behavior.

The implementations add checked resource ceilings and atomic mutation on failure. Native record equality compares complete chemical values rather than pointer addresses; observable candidate multiplicity is preserved separately. General RNA dataset redistribution and website terms are not inferred from source licenses. The full OpenMS core port remains in progress.

## Review and focused validation

All nine reference tests pass with current Rust/all features and Rust 1.85/no default features. Strict Clippy checks for this test target pass in both configurations, and the owned test file is formatted. All 28 pinned source hashes, eight fixture hashes (including the reused RNA registry table), literal source-line references and local documentation links were verified independently.

The production review covered all three algorithms, their finite branch behavior, ownership, append/replacement atomicity and resource checks. Three spectrum integration findings were corrected before handoff: an expression incompatible with Rust 1.85, missing accounting for copied name-vector slots, and the formula-only precursor path using a separate formula allowance. That path now shares the generator's work and allocation budgets. No additional scientific discrepancy remained after the reference suite passed; no expected scientific value was changed to accommodate an implementation result. The [validation report](VALIDATION.md) records the complete 993-test Rust 1.96 run, focused Rust 1.85 and no-default-feature checks, all-target strict Clippy, doctests, documentation, registry regeneration and package file-list checks.
