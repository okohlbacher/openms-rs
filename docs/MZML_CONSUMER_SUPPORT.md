# mzML consumers and transform operations

Source pin: `82ce5b373c97f934ffd9b1ffd80215ca66473d0b`. This increment implements the complete four-method `INTERFACES/IMSDataConsumer.h` contract and both `MzMLFile::transform` overloads, using the existing scientific decoder and experimental-header owner. It also implements `PeakFileOptions::FillData(false)` in scientific stream/path loading. Other concrete consumers, scan-mobility model completion, centroid inference, write-only options, general schema/semantic validation and the rest of `MzMLFile` remain their separately tracked operations.

## Native API

`interfaces::MSDataConsumer` is unconditional and object safe. All four methods are required: `set_expected_size`, `set_experimental_settings`, `consume_spectrum`, and `consume_chromatogram`. The last two receive exclusive mutable record borrows and return `Result<ControlFlow<()>>`; there are no silent callback defaults. Rust borrows/Drop replace the source pointer aliases and virtual destructor. The trait is also reexported through `format::mzml`.

`mzml::transform` and `transform_with_options` do not retain a hidden experiment. `transform_into` and `transform_into_with_options` append accepted callback-modified records to an existing experiment. The factory forms `transform_from` and `transform_from_into` accept `FnMut() -> Result<R>` with `R: BufRead`; options are explicit. The factory is invoked twice normally or once with `skip_first_pass`. Path forms reopen the file and detect plain/gzip/bzip2 input by magic. No seek or whole-file buffer is required. A changing file/factory between the two passes remains caller-owned behavior.

`TransformOptions` combines the existing `LoadOptions`/`ReadOptions` with two source flags and two native administrative budgets. Defaults are `skip_first_pass=false`, `skip_full_count=false`, 50 million administrative work units and 256 MiB administrative bytes. `TransformReport` distinguishes unannounced counts (`None`), announced raw counts, completed record callbacks and a soft stop.

## Source order and state

- `MzMLFile.cpp:178–230`: the first pass gathers fresh settings and **raw list declarations**, even when scientific filters are active. It calls expected-size before settings. `skip_first_pass` suppresses both calls. `skip_full_count` stops at the first list opening, after resolving its required processing reference but before reading its count, so the announcement is zero/zero. This override is independent of scientific `metadata_only` on the second pass.
- Signed 32-bit raw count parsing, the source `-1` sentinel and negative-count clamping are inherited from the existing count reader. Ordinary data-pass declarations still use the existing checked nonnegative/actual-count contract; this is not a promise to reproduce malformed source numeric states. The first pass stops when both raw counts are known, or reads through the document if one list is absent.
- `MzMLHandler.cpp:198–348,1398–1524`: accepted spectra and chromatograms have separate pools. Each complete pool is decoded, narrowed, aligned, sorted and validated before its first callback. Pool size zero is effective size one. Closing a list does not flush its leftovers. Closing mzML flushes spectra then chromatograms. With pool size two, three spectra followed by four chromatograms produce `S1,S2,C1,C2,C3,C4,S3`.
- `Continue(())` accepts the modified record. `Break(())` models `EndParsingSoftly`: it counts the current callback but does **not** retain its record, deliver pending records or inspect the unread tail. `Err` propagates. Setup errors suppress subsequent callbacks; a second open can fail after both setup callbacks. No callback mutation receives post-callback peak validation, sorting or realignment.
- `MzMLHandler.cpp:1186–1245,1499–1509,1540–1548`: retaining transforms seed the second pass with copied destination settings. Present identifier, sample, date, fraction and metadata keys overwrite; absent optional values persist. Contacts append; source files deduplicate against old and new values. Input instrument configurations replace that mapping. Unrelated settings and loaded path/type persist. Existing peak/array/processing graphs are not cloned or validated by the retaining operation. The original peak buffers retain identity across outer-vector growth.

The source nonretaining `AlwaysAppendData` flag only changes inaccessible temporary-map retention. The native nonretaining operation omits that storage; retaining always appends, as the source overload requires.

## Disabled data population

`fill_data=false` parses record metadata, scans, precursor/product settings and processing references, but creates no peak or auxiliary array values or descriptions. It does not base64/zlib/Numpress decode, narrow numeric payload, merge primary-array metadata or consume decoded-byte/element/declared-peak limits. Record filters still execute; point filters and sorting have no values to process.

XML bytes, namespaces, parameter/reference limits, record counts, descriptor counts and legal binary descriptions remain checked. The same allocation-free descriptor routine validates kind, precision, compression, Numpress effective type, primary floating encoding and explicit array length for both modes. Wrong/duplicate primary kinds and duplicate auxiliary names are rejected without population. Encoded payload length/content is deliberately not validated when data is unused; its XML text must still be legal ASCII. Missing an entire primary payload is allowed in this mode. Existing unsupported XML text forms and other scientific option guards remain unchanged.

## Failure and accounting boundaries

Destination settings and newly accepted records are staged. All logical destination contents remain unchanged on parsing, callback or resource failure. Final vector reservations occur before publication; capacity may change if a later reservation fails. Earlier callback effects are external and cannot be rolled back. Callbacks may retain copies, allocate data or deliberately produce an invalid scientific record; their work and payload are outside library accounting.

Administrative budgets precharge old settings cloning, pool/output vector growth, metadata merging and final descriptor moves/reservations. They do not charge arbitrary prior peak graphs. New decoded payload remains covered by the existing binary and scientific limits. Header parsing, source-file hashing/deduplication and seeded contact/source-file growth use the separate cumulative per-pass header allowance. Each parser pass receives its own ordinary XML/parameter/header/selection/Numpress allowance; none reset at a pool boundary. `max_data_pool_size` limits batching rather than requesting that entire allocation in advance. Nonretaining still uses the existing maximum physical-record limit, without a lifetime limit beyond one invocation.

Whole-record scientific exclusions keep the established native strict decode/validation policy when population is enabled. The [CPP-017](../OpenMS_CPP_ISSUES.md) correction keeps skip-chromatograms local to chromatogram delivery and announces zero chromatograms; it does not suppress headers or spectra. This increment identifies no additional original C++ defect. Native checked resource failures, atomic destination publication and explicit soft-stop reports are intentional adaptations.
